# 这份 chart 在渲染时改写的配置叶子：`files/cogneva.json` 是**源形态**，渲染产物
# 是**运行时形态**，两者在下面这些路径上按部署形态不同。
#
# 为什么要有这一份：静态基线（`deploy/k3s/cogneva-json-configmap.yaml`）从来是渲染
# 投影的抄件，而投递判据（`cog_core::config_sections`）拿交付的文档与编译进来的源文
# 件逐节比。投影一旦存在，这两件事就会在同一批字节上给出相反的判词：判据说 `system`
# 这一节变了（于是线上每个 apply 形态的部署都亮一条假告警），基线同步脚本又说两份文
# 档必须一致（于是它把源形态抄回去，投影被抹掉）。
#
# 所以投影只声明这一处，两侧都读它：同步脚本据此核对「差只落在登记过的路径上」，
# 判据据此把这几条叶子从两侧一起去掉再比。叶子从两侧都去掉是因为它本来就是部署形态
# 的值——源文件写不出、运行时才知道，拿它当「配错了」是错的；其余叶子照旧逐字比。
#
# 一行一条路径，`.` 分层，`#` 起头是注释。登记一条而 chart 不再改写它（两侧取值
# 相同）就是一条空登记，`cogneva` 的配置载体判据会把两种情形都判红。
